- Summary

- **Announcements and Upcoming Events**: Philippe Ombredanne announced attendance at the Linux Foundation Open Source Summit Europe in Prague to present on ClearlyDefined, Package-URL, and the OpenSSF scorecard with Bloomberg. Michael Herzog reported on ongoing experiments by Gemini with summaries and transcription fixes, noting the need for an agent markdown file to distinguish "Pearl" from "PURL".
- **Ecma Standards Approval and Housekeeping**: Michael Herzog provided an update on Ecma housekeeping for PURL 2nd Edition and VERS 1st Edition, noting that a meta standards issue regarding the JSON schema draft 2020-12 was deferred to standards specialist Aki Rose. A special TG2 meeting is scheduled for Tuesday 2026-10-06 to review and approve the PURL and VERS specifications, following a preliminary review where previous concerns were addressed.
- **Website Documentation and Publishing Workflows**: Michael Herzog explained that maintaining markdown documents for specifications and converting them to HTML proved difficult due to markdown's lack of expressive capabilities compared to Ecma templates. Michael Herzog and John Horan noted that maintainer access has been established for the Ecma TC54 repositories, which feature built-in GitHub workflows using `spec.html` (Ecmarkup) to automatically generate PDFs and GitHub.io staging websites.
- **Hugging Face Registration and Software ID Priorities**: Jon Moroney inquired about a pending pull request regarding a Hugging Face type, prompting Michael Herzog to agree to review active registrations and prioritize software ID advancement. Michael Herzog also noted that the newly approved Transparency Exchange API (TEA) might reduce pressure on software ID by handling commercial companies wanting to hide details behind permission structures, though Philippe Ombredanne raised concerns that TEA requires publicly-facing servers running code, creating provisioning and security challenges for organizations at scale.
- **Conda Package Type Update and Versioning**: Jaime Rodríguez-Guerra reported that the Conda steering council approved CEP 49 (https://github.com/conda/ceps/blob/main/cep-0049.md), modifying the namespace component to drop the channel name to better reflect modern commercial repositories. Michael Herzog advised opening a brief issue and a linked pull request to handle breaking changes in type definitions, while Philippe Ombredanne suggested adopting a date-stamped (CalVer) W3C-style publishing history and history page on the website to track schema changes.
- **Virtual Package Types and Python PEP 725 Alignment**: Jaime Rodríguez-Guerra presented a draft pull request for defining virtual package types to support PEP 725 (https://github.com/package-url/purl-spec/pull/1013), addressing needs such as compiler interfaces and alternative implementations (e.g., BLAS for numpy) where package authors do not care which specific provider is used. Jon Moroney and Philippe Ombredanne discussed namespaces using GitHub package linguist definitions and recommended adding qualifiers to trace which concrete packages provide virtual packages, with Jaime aiming to advance the proposal within a month to meet the Python packaging council's timeline.
- **SBOM Usage and Compiler Requirements for Virtual Packages**: Michael Herzog, Jon Moroney, and Philippe Ombredanne discussed the inclusion of virtual packages in software bill of materials (SBOMs), agreeing that virtual types should not be used in SBOMs when concrete implementations like specific compiler versions (e.g., GCC) are required, noting past issues where organizations used generic escape hatches making SBOMs unusable.
- **Software ID Registry and ASF Collaboration**: Philippe Ombredanne provided an update on integrating the PURL registry into the software ID, noting ongoing discussions with David Fisher and Piotr Karwasz from the Apache Software Foundation regarding the Apache trusted release project's desire to use software ID for Apache PURL.
- **Namespace Slashes and Encoding Resolution in PURL 3rd Edition**: Jaime Rodríguez-Guerra raised an ambiguity regarding slash separators between types, namespaces, and names, noting that current parsing rules are inconsistent. Philippe Ombredanne acknowledged the issue and proposed resolving it in the 3rd Edition of PURL by ensuring slashes never require encoding since they are not ambiguous in namespaces or qualifiers.
- The meeting was adjourned.
