- **Meeting Opening and Agenda Review**: Michael Herzog opened the community meeting under the Ecma TC54 code of conduct, reviewing running notes and agenda items. Philippe Ombredanne noted bad connection and tethering issues, proposing to discuss software ID and feedback from Prague.
- **Open Source Summit Europe in Prague - General Impressions and CRA**: Philippe Ombredanne and Jonatan Männchen shared feedback from the Open Source Summit Europe in Prague organized by the Linux Foundation, noting approximately 5,000 to 8,000 attendees and that the Cyber Resilience Act (CRA) is a major enterprise focus regarding due diligence requirements. Philippe Ombredanne presented at the conference on sharing clearing data and, alongside Steven Augustus from Bloomberg and the OpenSSF, on collecting and sharing raw security scan data. Jonatan Männchen noted receiving an Alpha Omega grant, ensuring continued funding for their work.
- **CVE Data Elements and Discussion Thread**: Jon Moroney discussed an ongoing conversation in the CVE world trying to document what concrete data should be made available in a CVE, noting cultural norms where participants demand features without use cases. Jonatan Männchen and Jon Moroney discussed how scanning for affected CVEs in Erlang uses specific data lock queries, and Jon requested that Jonatan Männchen share concrete examples to ground the discussion in practical use cases.
- **PURL Use Cases Request for Comments**: Michael Herzog introduced a new RFC discussion on PURL use cases to address backlog issues, drawing parallels to SPDX profiles or CycloneDX capabilities to define validation contexts, such as using Package-URLs without version ranges versus specific package downloads. Michael Herzog outlined two potential solutions: adding a new component or standardizing an API for tools to consume or provide PURL data. Jon Moroney noted that a common language for identifying objects is required across these use cases.
- **Test Suite Upgrade and Schema Changes**: Michael Herzog and Jon Moroney discussed the long-delayed test suite upgrade project (https://github.com/orgs/package-url/projects/10/views/1), prioritizing implementation of version 0.2 test schema changes (changing basic and advanced to required and recommended, roundtrip to validate, expected failure reason to expected message, and canonical to valid). Michael Herzog announced that PURL received an ISO number. Jonatan Männchen shared compliance test results from updating the Elixir PURL library.
- **VERS Test Suite Migration**: Michael Herzog and Philippe Ombredanne discussed the parallel effort for PURL and VERS test schemas, noting that the VERS test suite currently located in the aboutcode.org/univers repository contains more tests than the vers-spec repository and needs to be moved over to the package-url organization in GitHub to consolidate project resources.
- **Software ID and PURL Registry Update**: Michael Herzog and Philippe Ombredanne discussed updates to the software ID decision document (ADR – Architecture Decision Record) and JSON schema, noting engagement from the Linux kernel group and the Apache Software Foundation for non-Maven software. Jonatan Männchen raised questions about domain-based namespace rules and registry naming, leading to agreement to clarify the PURL type as operating without a package manager. Jonatan Männchen confirmed they are already publishing CVEs with a software-id PURL type.
- **Backfilling CVEs and Authorized Data Publisher Process**: Philippe Ombredanne discussed efforts to backfill CVEs with PURLs and an official request to the CVE secretariat to become an Authorized Data Publisher (ADP), noting that the process is being formalized. Jon Moroney noted that historical CVE labeling work and ecosystem data can be pulled directly from the GitHub database rather than redoing years of manual work.
- **CRA Expert Group and Identity Discussions**: Steve Springett shared insights from a CRA expert group SBOM workstrand call with Kate Stewart, noting discussions on software components, identity, and PURL being brought up multiple times for commercial and non-package use cases. Steve Springett highlighted that the group is motivated and actively engaged in solving identity challenges.
- **OSV.dev and GitHub Advisory Database Architecture**: Philippe Ombredanne criticized OSV.dev for data aggregation issues and problematic non-commercial licenses. Jon Moroney explained the historical and internal architecture of the GitHub Advisory Database (GHSA), detailing the relationship between repo advisories, the global database, and CVE records. Jonatan Männchen and Jon Moroney discussed structural challenges and dependencies between OSV, NVD, and GitHub data sources.
- **GitHub Data Model and Advisory Volume Growth**: Philippe Ombredanne noted that the format is great, but the site is problematic at scale when consuming the whole dataset, a shift that occurred over the last 12 to 18 months. Jon Moroney explained that GitHub's data model is structurally inefficient, causing discrepancies to compound and noise to grow as other systems ingest the data with their own latencies and format changes. Michael Herzog and Philippe Ombredanne highlighted a phenomenal growth and sea change in the total volume of advisories during the same 12 to 18-month period. Jon Moroney pointed out that a 1% noise rate combined with a thousandfold volume increase drives up the absolute noise floor, making it a critical problem that requires financial investment to resolve. Consensus was reached that systemic inefficiencies and surging advisory volumes are creating major scaling challenges.
- **Project Meridian and Defense Strategy**: Jonatan Männchen found the announcement impressive and noted it would involve many contracts, while Michael Herzog expressed skepticism that it would spark broad changes, countering earlier optimism. The participants acknowledged the high-profile nature of the initiative under MITRE but remained doubtful about its substantive impact on general defense changes.
- **European Regional Progress and Pragmatism**: Michael Herzog reported that ENISA is rising and that Europe is moving more quickly and pragmatically, driven partly by the Cyber Resilience Act and other factors. PURL will also be involved in these European efforts. The group acknowledged Europe as a region experiencing more rapid and pragmatic progress.
- **Architecture Decision Record Naming Cleanup**: Michael Herzog raised an issue: the current Decision Record for the new software-id PURL type does not follow the template and they committed to redrafting it in alignment with the template.
- **Historical Context of GitHub Data Models**: Jon Moroney shared a historical note regarding past synchronization meetings between GitHub and OSV during its peak. Jon recounted a conversation where they described the difference between repo advisories and global advisories to someone who was attempting to automate everything using a Google-like approach before realizing the data was entirely human-created. The discussion highlighted the historical challenges of dealing with discrepancies in automated systems handling human-generated data models.
- The meeting was adjourned.
