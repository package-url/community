## Notes

- Meeting minutes are being kept and will be published, and the meeting will be recorded with Google Meet video and Gemini "note-taking".
- Our code of conduct (link in agenda above) applies to this meeting.
- Introductions.
- Summary
  - Participants discussed concerns that the packageurl-js project needs a primary maintainer or core group. There are no project releases to-date.
  - Participants reviewed updates and the schedule for submitting VERS 1st Edition (new) and PURL 2nd Edition changes to Ecma TC54 for the Sept. 17 TC54 meeting.
  - Participants discussed the need for an AI policy. They acknowledged the importance of the human-in-control principle (not just human-in-the-loop) for code and other content generated by large language models or agents.
- **Meeting Introduction and Business**: Michael Herzog convened the meeting, confirming adherence to the TC54 code of conduct and noting that prior meeting minutes were available for review.
- **Package-URL JavaScript Project Maintenance**: Jon Moroney reported that an internal fork of the packageurl.js project (https://github.com/package-url/packageurl-js) contains features not present in the upstream version, leading to a proposal to upstream these contributions. The discussion highlighted the need for a clear maintainer or core group for the project, as the current status of the project health is unclear. Jon noted a lack of desire to assume long-term maintenance duties, seeking instead a one-time upstreaming of features to reduce their maintenance burden.
- **VERS Type Definition Schema**: Michael Herzog indicated that reserving types for the Version Range Specification (VERS) is not currently ripe for work but remains on the agenda. The team is currently tightening the initial VERS type definition schema, transitioning from version 0.2 to 1.0. The schema currently acts primarily as a registry of names, with future plans to include companion documentation for each VERS type to improve clarity.
- **Documentation Style Guide**: Michael Herzog clarified that the project follows an Ecma-compliant style guide, which requires using "shall" instead of "must" and prohibits capitalizing these terms. Additionally, the documentation follows British English spelling conventions, such as using "s" instead of "z" in words like "normalization," to align with ISO house style requirements.
- **Documentation Overhaul and Annexes**: The project is prioritizing the accuracy of Clause 5 in both the Package-URL and VERS specifications over updating how-to documentation. New informative annexes are being developed, including Annex B for recommended qualifiers and Annex C for the ABNF grammar for Package-URL strings, which was created by Jan Kowalleck.
- **Parsing and Normalization Techniques**: A distinction is being made between normative requirements and recommended practices for parsing. Michael Herzog proposed that "how to parse" and "how to build" documents should be separate from normative specifications, suggesting the creation of a "how to normalize" document to avoid mixing standard conformance with community-recommended techniques.
- **Artificial Intelligence Policy**: Jon Moroney raised the issue of developing a policy regarding the use of large language models for generating code or contributions, citing concerns about cognitive load and maintainability. Michael Herzog stated that while no formal policy is currently in place, the core principle being considered is "human in control," meaning contributors must remain responsible for the content they submit, a stance similar to those adopted by the Debian and Rust communities.
- **ECMA-427 and VERS Documentation Restructuring**: Michael Herzog updated the group on the restructuring of documents to mirror the Ecma standard format, with a specific focus on clarifying terminology in Clause 5, such as using "constraints" for VERS and "version ranges" for outside contexts. The group is currently seeking feedback on these documents, which are accessible within the project's GitHub repository.
- **VERS Type Definition Contributions**: Jon Moroney requested permission to contribute via pull requests to build up the VERS type definitions, as the current list in the repository is limited. Michael Herzog accepted this offer, noting that there is no desire to monopolize these tasks and welcoming the help.
- **ECMA-427 Second Edition Status**: The update to ECMA-427 is considered a maintenance release rather than a breaking change, with significant focus placed on the new informative Annex C for the PURL ABNF grammar. Michael Herzog detailed that the strategy involves capturing updates in a milestone and creating discrete pull requests for changes to each clause to ensure clarity and maintainability.
- **Documentation Maintenance Process**: The project is moving toward storing canonical schema definitions and type definitions on the [packageurl.org](http://packageurl.org) website rather than requiring navigation through the GitHub repository. This transition aims to improve accessibility for users needing to reference exact schema files.
- **Submission Timeline and Strategy**: Steve Springett and Michael Herzog established a timeline to finalize all documents by the following Tuesday or Wednesday to prepare for a vote on the September 17th agenda. The strategy involves submitting one pull request per clause to streamline the review process for TC54.
- **Patent Review and TC54 Requirements**: The team discussed the required 60-day patent review process that Ecma must complete following TC54 approval. Michael Herzog expressed hope that the patent review would be straightforward, noting that while it is a significant formality, the work has been planned to minimize complications.
- **Software ID Type Project Status**: The 'software-id' type project has been delayed due to the focus on Ecma submissions, though it remains a top priority alongside testing. Work is expected to resume once the Ecma-related documentation is completed, with potential use cases identified in the Linux kernel and Apache release packages.
- **Outreach and Communication Strategy**: Steve Springett suggested that the progress on 'software-id' usage in influential communities like the Apache Software Foundation should be promoted as a press release-worthy event to Ecma. Michael Herzog acknowledged the need for better outreach, noting that plans are underway to implement the Keila mailing list system and explore partnerships with existing consortia for project dissemination.
- The meeting was adjourned.
