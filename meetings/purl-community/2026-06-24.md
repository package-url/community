## Notes

- Meeting minutes are being kept and will be published, and the meeting will be recorded with Google Meet video and Gemini "note-taking".

- Introductions.
- Summary
  - The team outlined a transition from retroactive compliance to actionable testing examples for future registrations. This includes renaming test types to clarify validation goals and improving test schema definitions.
  - Attendees debated replacing restrictive communication channels with robust infrastructure for major standard changes. The group determined that relying on legacy tools for governance is insufficient for future expansion.
  - Attendees discussed a policy to require transparency when contributors use machine learning tools to generate contributions - especially pull requests.
  - Additionally, normalization rules were reframed as recommendations to guide users toward canonical implementation formats.
- **Meeting Opening and Administration**: Michael Herzog hosted the PURL community meeting on behalf of AboutCode, noting that the session was recorded using Google Gemini and workspace tools strictly for producing minutes. It was confirmed that recordings are not published, and the team adheres to the ECMA code of conduct. No objections were raised regarding the previous meeting's minutes, which are editable by PR.
- **vcpkg PURL Type Request**: Jamie Magee presented the status of the vcpkg PURL type request, confirming that previous outstanding questions had been addressed. Michael Herzog stated that while there is no formal review process, the team intends to review the request this week, noting that the primary challenge is ensuring sufficient community involvement. Regarding testing, the team requested that contributors provide examples of failing tests that illustrate common ecosystem patterns, rather than only successful test cases. Jamie Magee agreed to add the package logo to the pull request comments, and the team will stage the approval on GitHub pages before updating the production site on DreamHost.
- **Git Type and Repository URL Qualifier**: Jon Moroney proposed forbidding the "repository_url" qualifier for the Git type to prevent redundancy, as the Git type already includes a location for code. Discussion arose regarding the potential use of this qualifier for identifying mirrors, leading to a debate on whether to strictly prohibit it or treat it as a recommendation. The group consensus was that prohibiting qualifiers is difficult, and the team will rely on recommendations rather than strict prohibitions for the time being. The team acknowledged some minority dissent regarding the Git type but agreed to move forward.
- **Test Schema and Conformance Definitions**: Michael Herzog introduced a draft document to update the current test overview. The team is refining terminology to distinguish between "base" tests, which align with "shall" requirements in ECMA-427, and "advanced" tests, which align with "should" recommendations. To support these improvements, the team plans to modify the test schema to replace the field "expected_failure_reason" with "expected_message," allowing for better handling of advisory messages and non-conformance cases.
- **Schema Change - Renaming "roundtrip" to "validate"**: Michael Herzog proposed renaming the "roundtrip" test type to "validate". The rationale is that the term "roundtrip" implies a deserialization-serialization sequence that may be redundant if input is already canonical. The new "validate" test type would clarify that the test is intended for validation, allowing for the flagging of non-canonical input as an error.
- **Future Test Development and Community Guidance**: Michael Herzog emphasized the importance of simplicity in testing and the need for clear guidelines for contributors. While the team will not retroactively hold current contributors like Jamie Magee to new, evolving standards, they plan to reach out to contributors to help illustrate common errors through new test cases. The goal is to provide concrete, actionable examples for future registrations.
- **Communication Channels and Slack Access**: Jon Moroney and Jamie Magee raised concerns about difficulty accessing the AboutCode Slack workspace via the link on the GitHub repository. Michael Herzog clarified that there are two separate workspaces: one for OWASP (which has a wider audience) and one for AboutCode (which has higher activity). Participants confirmed they were able to access the AboutCode workspace after troubleshooting the invite link. Michael Herzog agreed to update the GitHub README to clearly distinguish between the two channels and provide functional links.
- **Communication Infrastructure and Governance**: The team discussed the need for improved communication tools to share announcements, noting that relying solely on Slack is insufficient for formal governance. They are evaluating options like Listmonk or GitHub Pages to facilitate formal two-week notification periods for major changes to the standard, avoiding reliance on Google Groups, which were deemed clunky.
- **Normalization Rules and Canonicalization**: Michael Herzog discussed normalization rules, specifically addressing the handling of extra slashes in PURL types (e.g., "pkg://"). The team plans to interpret these rules as "should" recommendations to guide users toward canonical forms. The objective is to provide helpful feedback messages that discourage non-canonical formats, as these can break "naive" consumer implementations.
- **Machine Learning Policy**: Michael Herzog initiated a discussion on the policy regarding content generated by machine learning. The team emphasized a preference for the term "machine learning" over "AI" and stressed the importance of human accountability and transparency. The group agreed that if machine learning tools are used to generate pull requests, that usage should be declared. This is particularly critical for AboutCode, where strict compliance is required, and current machine learning tools cannot effectively track code provenance.
- **Logo Branding and Documentation Cleanup**: Participants discussed the logo for the vcpkg, and Jamie Magee agreed to recommend the appropriate usage. Michael Herzog noted past challenges with strict branding policies from other projects, such as the Yocto Project. Additionally, a minor cleanup effort was announced to move documentation files from a top-level "types-doc" folder to a new "docs" folder to improve repository organization.
- The meeting was adjourned.
