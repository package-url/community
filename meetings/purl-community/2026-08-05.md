- Summary
  - Participants formalized new contributor additions and discussed the potential movement of the https://github.com/aboutcode-org/univers project into the package-url GitHub organization.
  - The group reiterated support for changes to the PURL and VERS test schemas and test suites to clearly distinguish between test cases required for conformance and those that are recommended for normalization.
  - The group discussed the timeline and priorities for the September submission of the PURL 2nd edition and VERS 1st edition standards to Ecma.
  - Philippe proposed a PURL change to merge the "namespace" and "name" components into a single PURL component. The group agreed that this needs further discussion and is not in scope for the current PURL/ECMA-427 2nd edition standard.
  - The group discussed a proposal to change the approach for managing test cases from grouping them in files to one file per test case.
  - The group discussed concerns about a regression in CycloneDX 2.0 that reduces the amount of component identifier information recorded compared to CycloneDX 1.7.
- **Meeting Opening and Administration**: Michael Herzog opened the PURL Community meeting, reminding attendees to follow the ECMA TC54 code of conduct. The meeting is recorded to facilitate the creation of minutes, and participants were informed that records are removed approximately one month after the minutes are approved. Michael Herzog noted that because the Gemini summarization feature has decreased in performance, they are currently performing manual summarization for the meeting notes.
- **univers Organization and Membership**: Philippe Ombredanne presented three agenda items: the addition of Immanuel Kunz as a contributor to univers, a Request for Comments regarding the potential movement of univers to the PURL organization, and the addition of Jaime Rodríguez-Guerra as a contributor. Philippe Ombredanne explained that Jaime Rodríguez-Guerra, an open source contributor associated with the UK-based company Quansight, has been active in writing Python enhancement proposals to improve the tracking of non-Python packages in Python wheels using PURL and univers.
- **Updates on Issue 82 and Issue 69**: Michael Herzog confirmed that feedback regarding Immanuel Kunz's work on issue 69 was received and that the team plans to approve the changes. Immanuel Kunz stated that no further discussion was required for issue 82. Regarding issue 69, which concerns whitespace handling, Immanuel Kunz initiated a discussion about potential contradictions in existing types, specifically regarding whether the lexicographic VERS type should permit whitespace.
- **Required Versus Recommended Test Procedures**: Philippe Ombredanne expressed a preference for stricter procedures, stating that the team should avoid accepting non-canonical PURL inputs in their API. Michael Herzog observed that while PURL has a legacy of leniency, the VERS project offers a clean slate, and the team discussed whether the "recommended" category of test cases should be removed or clarified in documentation rather than enforced via test cases.
- **Test Schema Updates and Documentation Strategy**: Michael Herzog reported that new test schemas for PURL and VERS were released, incorporating "required" and "recommended" terminology. The team discussed shifting from a model that relies solely on test cases to one where documentation clearly outlines normalization rules and conformance requirements. It was agreed that test cases remain useful as specific data points for implementers.
- **Automation of Test Suite Updates**: John Horan is currently working on scripts to automate the updating of the test suite. Michael Herzog outlined a two-step process involving renaming fields (e.g., changing "roundtrip" to "validate") and cleaning up test cases, which is necessary for the PURL type request process and the overall schema framework.
- **ECMA Standard Preparation and Timeline**: Philippe Ombredanne confirmed time blocked on their calendar to work on PURL and VERS schemas. Michael Herzog clarified that the current test schema updates are not intended for the September ECMA submission deadline but are preparatory work. The goal is to submit a 1.1 or 1.2 release for the ECMA-427 2nd Edition to avoid breaking changes, with more significant updates reserved for a future version 2.0.
- **JSON Schema Version Upgrade**: The team discussed upgrading the PURL type definition JSON Schema to version 2020-12. Michael Herzog noted unresolved questions regarding the impact on Golang implementations but suggested that they would investigate further, noting that there was insufficient information about other potential impacts at the time of the meeting.
- **Proposal for Namespace and Encoding Changes**: Philippe Ombredanne proposed a revamp of the core specification to merge the concepts of "namespace" and "name" into a single entity that can be segmented with slashes, removing the requirement to percent-encode forward slashes ('/'). This proposal aims to simplify parsing and resolve specific issues with Go modules. While Michael Herzog noted the importance of maintaining clarity for project owners, the team agreed to discuss the proposal further.
- **Atomic Test Case Structure Proposal**: Michael Herzog presented issue 765 (https://github.com/package-url/purl-spec/issues/765), which proposes atomizing test cases into individual JSON files with unique identifiers to improve feedback for tool implementers. Philippe Ombredanne supported this, noting that it optimizes for user feedback despite requiring more effort from test creators. The team agreed to test this structure by implementing it in a Python branch. This change is expected to be particularly useful for the univers library, which contains approximately 8,000 tests.
- **CycloneDX 2.0 Validation Concerns**: Matt Rutkowski raised concerns regarding CycloneDX 2.0, noting that it has merged component identity types into a list of enumerations without providing a mechanism to associate validation schemas, which prevents programmatic validation of PURL identities. Matt Rutkowski and Philippe Ombredanne expressed that this represents a regression in functionality. The participants agreed that this is a substantive issue and that they should raise it with the TC54 committee before the August 20th deadline to ensure there is a way to link to validation schemas.
- **CycloneDX 2.0 Identifier Data Loss**: Philippe Ombredanne and Michael Herzog discussed a recent change where specific data associated with identifiers was removed and replaced, which they characterize as a "dumbing down" of the schema. Michael Herzog suggested this reduction may have been intended to accommodate new identifiers, but Philippe Ombredanne identified the loss of detailed information as problematic.
- **Communication with Steve Springett**: Michael Herzog suggested that Philippe Ombredanne should be the one to contact Steve Springett regarding these schema changes.
- **Identifier Inflation and AI Development**: Philippe Ombredanne noted the "inflation of identifiers" and expressed disinterest in aggregating hardware information into a single location.
- The meeting was adjourned.
